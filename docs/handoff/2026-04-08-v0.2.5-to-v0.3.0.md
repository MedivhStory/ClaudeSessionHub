## 项目概况

原生 macOS SwiftUI 任务管理器，管理 Claude Code 会话。读取 `~/.claude/` 本地数据，提供 Project→Session 层级浏览、健康信号、智能命名、AI 增强理解、一键恢复。

```
SessionStore (@Observable, @MainActor)
  ├─ ScanCoordinator (actor)
  │    └─ ClaudeProvider (dynamic baseDirectoryProvider)
  │         ├─ discoverSessions() → [SessionSummary]
  │         ├─ extractSignals(for:) → SessionSignals
  │         └─ extractKeyTurns(for:maxTurns:) → [String]
  ├─ SignalExtractor (dynamic baseDirectoryProvider)
  │    ├─ historyDisplayTexts(for:) → [String]
  │    └─ taskSignals(for:) → [TaskSignal]
  │
  │  ── 规则层 ──
  ├─ SessionTitleStrategy (protocol)
  │    └─ RuleTitleStrategy
  │         ├─ generateTitle(from: SessionSignals) → GeneratedTitle
  │         ├─ generatePlaceholderTitle(from:) → GeneratedTitle?
  │         ├─ extractLastProgress(from:) → String?
  │         └─ shouldGenerateFirstTitle(for:) → Bool
  ├─ TitleStore (titles.json)
  │    ├─ titles, progress, userNotes
  │    └─ TitleSource: .rule / .placeholder
  │
  │  ── LLM 增强层（v0.2.5 新增）──
  ├─ LLMEnhancer (standalone service)
  │    └─ enhance(signals:rawTurns:basedOnLastActiveAt:) → LLMUnderstandingSnapshot?
  ├─ LLMClient (OpenAI-compatible HTTP)
  │    └─ complete(systemPrompt:userMessage:maxTokens:) → String
  ├─ LLMPrompts (prompt templates)
  ├─ UnderstandingStore (understanding.json) ← 完全独立于 TitleStore
  │    └─ LLMUnderstandingSnapshot: title, progress, summary, modelName, generatedAt, basedOnLastActiveAt
  │
  │  ── 其他存储 ──
  ├─ LabelStore (labels.json, legacy)
  ├─ ArchiveStore (archived.json)
  ├─ SettingsStore (settings.json)
  │    └─ LLMConfig: endpoint, apiKey, modelName
  └─ UnderstandingStore (understanding.json)
```

### 数据流

**规则层（自动，每次扫描）：**
```
performScan → coordinator.scan() → sessions sorted
  → generateTitlesForNewSessions:
      extractSignals → enrich → gate check
      → .rule title / .placeholder / skip
```

**LLM 层（手动触发）：**
```
enhanceWithLLM(for: ref):
  extractSignals → enrich → extractKeyTurns
  → LLMEnhancer.enhance → LLMUnderstandingSnapshot
  → UnderstandingStore.setSnapshot
```

**批量增强：**
```
batchEnhanceLLM(sessions: [SessionRef]):  // caller 传入显式列表
  for each ref:
    skip if fresh (non-stale) enhancement exists
    enhanceWithLLM → rate limit 500ms
```

### 状态机

**规则层标题：**
| 当前状态 | Gate Pass | Gate Fail |
|---|---|---|
| 无标题 | 生成 .rule | 生成 .placeholder |
| .placeholder | 自动升级为 .rule | 跳过 |
| .rule | 跳过 | 跳过（不降级） |

**LLM 层快照：**
- 完全独立于规则层状态机
- 只在用户手动触发时生成
- stale 判断：`session.lastActiveAt > snapshot.basedOnLastActiveAt`
- stale 只是展示态，不触发自动重跑

**UI 显示优先级（当前硬编码）：**
- 标题：AI snapshot.title > rule smart title > cleaned original
- 摘要：AI summary first sentence > AI progress > rule progress > currentTaskSummary

**注意：** 当前 AI > rule 的显示优先级是硬编码的，不是用户可选的。v0.2.5 brainstorming 中讨论过"用户可选默认显示层"（全局设置控制折叠态优先展示 AI 还是规则），但最终结论是 **LLM 绝对比规则更可读，规则只做保险对比**，因此 v0.2.5 没有做全局切换设置。如果 v0.3 需要改变这个策略，需要在 SessionTileView.displayTitle 和 bestSummary 中加入 Settings 切换逻辑。

## 已知限制 & v0.3 候选

### 功能缺口
- **SSH 远程管理** — v0.2 只留了架构设计，未实现
- **Codex provider** — 仍是 stub
- **字号可配置** — 当前字号固定，用户要求做 Settings slider
- **搜索语义增强** — v0.2.5 没做，搜索仍是加权关键词
- **AI 摘要语言** — prompt 固定中文，英文模型可能质量下降

### 代码审查遗留（P2）
- API key 存在 plaintext JSON（应迁移 Keychain）
- LLMEnhancer 三次 API 调用串行（可并行 progress+summary）
- `historyTextsCache` 缺 `@MainActor` 标注
- `relativeTime` 在两个 view 里重复
- `readSampledUserTurns` 性能：当前仍需 readAllEntries 再筛选

### 产品遗留
- AI 标题对超长 session 仍可能偏向末尾操作（prompt 改善后好转但不完美）
- 部分 session 的 AI 进展返回空字符串
- 批量增强无进度指示器（用户不知道跑了几个）

## 铁则（从 v0.2 继承，v0.3+ 继续遵守）

1. **Hub = 管理器 + 理解器，不是执行器**
2. **离线优先，LLM 是增强不是依赖**
3. **先让用户看懂全貌，再考虑替用户做事**
4. **UnderstandingStore 完全独立于 TitleStore**
5. **LLM 只在用户显式触发时调用，不绑定扫描**
6. **stale 只是展示态，不触发自动重跑**

## v0.3 方向建议

基于用户在 v0.2/v0.2.5 中表达的需求：

1. **SSH 远程管理** — 多机 session 聚合，RemoteProvider
2. **字号/UI 可配置** — Settings 里加 font scale slider
3. **批量增强进度** — 进度条或计数器
4. **API key 安全** — 迁移到 macOS Keychain
5. **搜索增强** — 可选语义搜索（embedding 或 LLM rerank）
6. **AI prompt 语言自适应** — 根据 session 语言选择 prompt 语言
