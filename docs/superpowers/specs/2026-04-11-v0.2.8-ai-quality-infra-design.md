# v0.2.8 AI Quality Infrastructure — Design Spec

This spec is the single source of truth for v0.2.8. All implementation decisions below are locked. Any deviation during implementation requires returning to this document and updating it explicitly with rationale, not silently diverging.

Readers should treat this document as exhaustive. It intentionally repeats details across sections so that future agents reading any single section can act without cross-referencing session history.

---

## Section 1 — Scope & Non-Scope

### 1.1 Version positioning

**v0.2.8 is the AI Quality Infrastructure version**, a single-mainline release. Its sole purpose is to replace the current "change prompts → eyeball outputs → hope for the best" quality loop with a mechanically verifiable, reproducible, auditable quality gate.

### 1.2 Mainline scope (4 items, mutually supporting, not a flat to-do list)

**1. Two-layer eval infrastructure**

- **Layer 1 — provider/signals/sampling deterministic unit tests**  
  Pure Swift, run by CI on every PR. No LLM calls. No API keys. Millisecond-level. Protects `VersionMentionExtractor`, `MilestoneSampler`, `readSampledUserTurns`, and `LLMPrompts` rendering from regressions during day-to-day iteration.

- **Layer 2 — `swift run eval-harness live` end-to-end release gate**  
  Runs manually on a pre-tag candidate commit. Calls the canonical LLM provider (DashScope qwen-plus, temperature=0). Produces a structured violations list and a fully traceable run artifact. The tag may only be created after this gate passes.

  **Release gate binding rules** (mechanically enforced by `check-artifact`, not review discipline):
  - Gate runs on the candidate commit before the tag is created
  - `artifact.commitSHA` must equal the SHA that the tag will point at
  - `artifact.promptBuilderHash` must equal the current SHA256 of the four `LLMPrompts` prompt assets (see §2.5 and §7.1 I-5)
  - `artifact.dslSchemaVersion` must equal the current harness DSL schema version
  - `artifact.mode` must be `"release"`
  - `artifact.provider`, `artifact.model`, `artifact.temperature` must equal the values in `EvalHarnessCore.CanonicalGate`
  - `artifact.gateResult` must be `"PASS"`
  - Any mismatch → `check-artifact` exits non-zero → tag flow refuses to continue

**2. Initial 6 reference fixtures**

- 2 real desensitized snapshots (quality baseline, capturing real long-session noise)
- 4 handwritten synthetic fixtures (regression baseline), each pinning one known failure mode:
  1. Version-number hallucination
  2. Long-session tail bias
  3. AI progress empty string
  4. Cross-version session title range expression

The word "initial" is deliberate: after v0.2.8 ships, the fixture set may grow (v0.2.8.x can add cases without modifying the DSL or harness core). The 6-count is a starting point, not a hard ceiling.

Desensitization is scripted: `scripts/eval/desensitize_session.swift` plus an independent pre-check verifier that is deliberately decoupled from product code.

**3. Structured `versionMentions` signal**

- New `VersionMention` model (`raw`, `normalized`, `selectedSource`, `occurrenceCount`)
- New `VersionMentionExtractor` service (strict semver regex, scans 6 signal sources)
- `SessionSignals` gains a `versionMentions: [VersionMention]` field
- Population point locked to `ClaudeProvider.extractSignals(for:)` tail
- Replaces the hardcoded inline keyword filter currently living in `LLMPrompts.swift:45-68`

**4. Sampling chain reconstruction**

- New `MilestoneSampler` (version anchors + head/tail + time-uniform fill, adaptive K with floor 4 / ceiling 8, mandatory > K priority truncation rule)
- `JSONLParser.readSampledUserTurns` rewritten as two-pass streaming with bucket-center selection (no longer depends on `readAllEntries`, O(K) memory, deterministic)
- `LLMPrompts.titleInput` deletes its inline sampling code and consumes a structured `[MilestoneEntry]` instead
- All three system prompts (`titleSystemPrompt`, `progressSystemPrompt`, `summarySystemPrompt`) share a single appended "version number clause", with the zero-detection branch applied to title / progress / summary uniformly

### 1.3 Verification outcomes (gate outputs, not flat scope items)

The three known failure modes and one positive expression are **outcomes of passing the above four scope items**, not independent line items. They are verified by the eval harness through the constraint DSL:

| Failure mode | Verification mechanism |
|---|---|
| Version-number hallucination (e.g. case 6a7b8e24) | Zero-detection prompt clause + `maxRegexMatchCount` constraint on all three output fields |
| Long-session tail bias | `MilestoneSampler` version anchors + time-uniform fill |
| AI progress empty string | `mustNotBeEmpty` + `minLength` + `mustNotEqual` constraints |
| Cross-version session title range expression | `mustMatchRegex` constraint |

### 1.4 Non-scope (explicitly not done in v0.2.8)

| Item | Deferred to | Reason |
|---|---|---|
| SSH remote management | v0.3.0 mainline | Independent direction, no coupling to AI quality infra |
| Font size / UI configurability | v0.2.8.x or v0.2.9 | UX scope, creep risk |
| Codex provider real implementation | Unscheduled | Not quality infrastructure |
| LLMEnhancer parallelization of progress+summary calls | v0.2.8.x | Tech debt, stabilize before optimizing |
| AI prompt language adaptation (CN/EN switching) | v0.2.9 | Cross-language testing is expensive |
| LLM-as-judge verifier layer | v0.2.8.x+ | Trigger: rule verifier must first be proven insufficient for a real failure mode |
| DSL operators `mustNotMatchRegex`, `minRegexMatchCount`, named token sets, automatic schema migration | v0.2.8.x+ | Extend on demand |
| CalVer version number matching | v0.2.8.x+ | Evaluate when a real CalVer session is encountered |
| **Multi-provider eval matrix** (OpenAI / DeepSeek / Ollama comparative gate) | v0.2.9+ | v0.2.8 locks a single canonical provider (DashScope qwen-plus). Cross-provider drift must not pollute the baseline |
| Keychain migration for API key storage | Post Apple Developer signing | Orthogonal to this scope; listed here only to prevent amnesia |

### 2.3 `expected.json` schema and DSL operators

Canonical example (for the same fixture as §2.2):

```json
{
  "schemaVersion": "1",
  "id": "synthetic-version-hallucination-01",
  "title": {
    "mustNotContain": ["v0.2.0", "0.2.0"],
    "maxRegexMatchCount": {
      "pattern": "(?i)v?\\d+\\.\\d+(\\.\\d+)?",
      "n": 0
    },
    "maxLength": 30,
    "mustNotBeEmpty": true
  },
  "progress": {
    "mustNotContain": ["v0.2.0", "0.2.0"],
    "mustNotBeEmpty": true,
    "mustNotEqual": ["无明确进展"],
    "minLength": 10
  },
  "summary": {
    "mustNotContain": ["v0.2.0", "0.2.0"],
    "maxLength": 150
  }
}
```

**9 supported operators** (schemaVersion "1"):

1. `mustContainAny: [String]` — the output must contain at least one of the listed substrings
2. `mustContainAll: [String]` — the output must contain every listed substring
3. `mustNotContain: [String]` — the output must not contain any of the listed substrings
4. `mustNotEqual: [String]` — the output (whole string) must not equal any listed string
5. `mustNotBeEmpty: Bool` — if `true`, the output (after trim) must have length > 0
6. `minLength: Int` — character count lower bound (inclusive)
7. `maxLength: Int` — character count upper bound (inclusive)
8. `mustMatchRegex: String` — the full output must match the given regex (anchored or not, per pattern)
9. `maxRegexMatchCount: { pattern: String, n: Int }` — the number of non-overlapping regex matches in the output must be ≤ n

All string operators use Unicode NFC-normalized, case-sensitive substring comparison unless otherwise specified inside the DSL string itself (regex patterns may declare `(?i)` for their own case folding).

**Optional fixture-level field** (not per-field): `verbatimMatchJustification: String?` — opt-in human-readable reason when a long substring constraint is deliberately copied from input text. See §2.7.

**DSL fail-closed rules**:
- `schemaVersion` absent → `HarnessConfigError.schemaMissing`
- `schemaVersion` newer than harness support → `HarnessConfigError.schemaTooNew`
- No automatic schema migration. Ever.

### 2.4 Verifier output

```swift
struct VerificationResult: Sendable {
    let fixtureID: String
    let passed: Bool
    let violations: [Violation]
    let snapshot: LLMUnderstandingSnapshot   // actual LLM output, recorded in artifact
}

struct Violation: Sendable {
    let field: Field
    let constraint: ConstraintKind
    let expected: String   // human-readable constraint description
    let actual: String     // excerpt of the actual output that violated
}

enum Field: String, Sendable, Codable {
    case title, progress, summary
}

enum ConstraintKind: String, Sendable, Codable {
    case mustContainAny, mustContainAll, mustNotContain, mustNotEqual
    case mustNotBeEmpty, minLength, maxLength
    case mustMatchRegex, maxRegexMatchCount
}
```

**Non fail-fast aggregation**:
- All fields of a single fixture are verified against all constraints; every violation is collected into `violations`
- Across fixtures, all fixtures are verified; a single failing fixture does not abort the run
- `HarnessConfigError` cases are similarly aggregated at startup (see §2.6)

**`promptBuilderHash` — precise definition** (this is load-bearing for gate integrity):

```
canonicalBlob =
  "titleSystemPrompt=" + <LLMPrompts.titleSystemPrompt string>          + "\n" +
  "progressSystemPrompt=" + <LLMPrompts.progressSystemPrompt string>    + "\n" +
  "summarySystemPrompt=" + <LLMPrompts.summarySystemPrompt string>      + "\n" +
  "titleInputSource=" + <Swift source of LLMPrompts.titleInput function body>

promptBuilderHash = "sha256:" + hex(sha256(canonicalBlob.utf8))
```

- The first three are runtime `static let` string values, read directly at harness startup
- The fourth is the **source text of `LLMPrompts.titleInput` function body**, captured at build time by a SwiftPM build tool plugin (see §6.2). This is stored in a generated constant `GeneratedPromptSource.titleInputFunctionSource` that lives in the plugin work directory and is auto-linked into `EvalHarnessCore` at build time.
- The captured function body includes signature, braces, and full body text, byte for byte. Whitespace-only or comment-only changes intentionally invalidate the hash, because they indicate the prompt construction logic was touched.

**Why capture the function source, not just its output**: `titleInput` is a pure function of `SessionSignals`. Two distinct function bodies can produce identical outputs for one particular input while differing for others. The gate must track "the prompt construction logic as a whole", not "one run's output format".

`promptBuilderHashInputs` holds the raw strings used to produce the hash, so the artifact is human-readable and independently re-hashable.

### 2.6 `HarnessConfigError` model

```swift
public enum HarnessConfigError: Error, CustomStringConvertible {
    case unpairedFixture(id: String, missing: PairSide)
    case schemaMissing(id: String, file: String)
    case schemaTooNew(id: String, found: String, supported: String)
    case malformedInput(id: String, reason: String)
    case malformedExpected(id: String, reason: String)
    case fixtureIDMismatch(prefix: String, inputID: String?, expectedID: String?)
    case invalidKindMetaCombination(id: String, reason: String)
    case invalidRegex(id: String, field: String, pattern: String, error: String)
    case invalidConstraintValue(id: String, field: String, constraint: String, reason: String)
    case verbatimMatchRequiresJustification(id: String, field: String, value: String, length: Int)
    case promptSourceMissing

    public var description: String { /* human-readable diagnostic per case */ }
}

public enum PairSide: String, Sendable {
    case input, expected
}
```

**Startup validation order** (all steps aggregate errors, never fail-fast):

1. File pairing (`unpairedFixture`)
2. JSON parse (`malformedInput`, `malformedExpected`)
3. Schema version (`schemaMissing`, `schemaTooNew`)
4. Three-way ID consistency (`fixtureIDMismatch`)
5. Kind / meta combination (`invalidKindMetaCombination`)
6. Regex compilability (`invalidRegex`)
7. Constraint value validity, e.g. `n >= 0`, `minLength <= maxLength` (`invalidConstraintValue`)
8. Verbatim match pre-check (`verbatimMatchRequiresJustification`) — see §2.7
9. Prompt source presence (`promptSourceMissing` — only triggered if build plugin somehow produced empty source; normally prevented at build time)

All errors from all fixtures are collected into `[HarnessConfigError]` and reported together at startup. If any error exists, the run aborts after reporting. Sub-agents fixing fixtures get the complete correction list in one pass.

### 2.7 Pre-check: verbatim match heuristic

```swift
func precheckVerbatimMatch(
    input: FixtureInput,
    expected: ExpectedConstraints
) -> [HarnessConfigError] {
    let THRESHOLD = 20  // characters

    // Build haystack from all input text fields
    let haystack: String = [
        input.signals.firstUserIntent,
        input.signals.lastUserIntent,
        input.signals.lastAssistantProgress,
        input.signals.taskSubject,
        input.signals.taskDescription
    ].compactMap { $0 }
     .joined(separator: "\n")
    + "\n" + input.signals.historyDisplayTexts.joined(separator: "\n")
    + "\n" + input.rawTurns.joined(separator: "\n")

    var errors: [HarnessConfigError] = []

    // Scan every string constant in expected constraints
    for (fieldName, fieldConstraints) in expected.allFields() {
        let stringConstants: [String] =
            (fieldConstraints.mustContainAny ?? []) +
            (fieldConstraints.mustContainAll ?? []) +
            (fieldConstraints.mustNotContain ?? []) +
            (fieldConstraints.mustNotEqual ?? [])

        for s in stringConstants {
            if s.count >= THRESHOLD && haystack.contains(s) {
                if expected.verbatimMatchJustification == nil {
                    errors.append(.verbatimMatchRequiresJustification(
                        id: expected.id,
                        field: fieldName,
                        value: s,
                        length: s.count
                    ))
                }
            }
        }
    }
    return errors
}
```

**Threshold**: 20 characters, defined as a compile-time constant in harness source. Sub-20-char substrings (common phrases like "单测通过") have non-negligible incidental collision rates with real input text, so the heuristic would false-positive on them. ≥20 chars collisions are almost always deliberate copy-paste.

**Escape hatch**: Setting `verbatimMatchJustification` to a non-nil human-readable reason bypasses the check for that entire fixture. The justification is logged (not validated for content), so anyone reviewing the fixture sees why an exact string match was intentional.

## Section 3 — `versionMentions` Signal and LLMPrompts Integration

### 3.1 `VersionMention` model

**File**: `Sources/ClaudeSessionHub/Models/VersionMention.swift`

```swift
import Foundation

public struct VersionMention: Sendable, Codable, Equatable {
    public let raw: String           // original match, preserving case/prefix: "V0.2.5", "v0.2.5", "0.2.5"
    public let normalized: String    // lowercase, leading 'v' stripped: "0.2.5"
    public let selectedSource: SourceRef
    public let occurrenceCount: Int

    public init(
        raw: String,
        normalized: String,
        selectedSource: SourceRef,
        occurrenceCount: Int
    ) {
        self.raw = raw
        self.normalized = normalized
        self.selectedSource = selectedSource
        self.occurrenceCount = occurrenceCount
    }
}

public struct SourceRef: Sendable, Codable, Equatable {
    public let kind: SourceKind
    public let index: Int?    // 0-based; non-nil only when kind == .history

    public init(kind: SourceKind, index: Int? = nil) {
        self.kind = kind
        self.index = index
    }
}

public enum SourceKind: String, Sendable, Codable, CaseIterable {
    case history
    case firstUserIntent
    case lastUserIntent
    case lastAssistantProgress
    case taskSubject
    case taskDescription
}
```

**Semantic definition of `selectedSource`** (important, the name is deliberately not `firstSeenIn`):

> `selectedSource` is the first source in `VersionMentionExtractor.scanOrder` in which the version was encountered. `scanOrder` is a priority list (see §3.2), not a timeline. The field has nothing to do with where the version first appeared on the session's timeline. If a future feature needs the timeline-first source, it must introduce a separate field; do not overload `selectedSource`.

**`SourceRef.index` semantics**: strictly 0-based. JSON serialization, prompt rendering (`history[N]`), and all tests use 0-based. No 1-based representation is permitted anywhere.

### 3.2 `VersionMentionExtractor` service

**File**: `Sources/ClaudeSessionHub/Services/VersionMentionExtractor.swift`

**Contract**:
- Pure function: no state, no I/O, thread-safe
- Input: a fully assembled `SessionSignals`
- Output: `[VersionMention]`
- Must not read any file, must not depend on any store
- Not allowed to mutate its input

**Regex**: strict semver

```
(?i)v?\d+\.\d+(\.\d+)?(-[A-Za-z0-9.]+)?
```

Examples matched: `v0.2.5`, `0.2.5`, `V0.2.5`, `v1.0.0-rc.1`, `0.2.5-beta`
Examples not matched: `v2` (no dot), `2024.Q3` (not semver), `abc.def` (not digits)

**Scan order constant** (separated from `SourceKind` enum declaration order on purpose, so re-declaring the enum does not silently change scan semantics):

```swift
public enum VersionMentionExtractor {
    public static let scanOrder: [SourceKind] = [
        .taskSubject,
        .firstUserIntent,
        .lastUserIntent,
        .taskDescription,
        .history,
        .lastAssistantProgress
    ]
}
```

**Algorithm**:

```
extract(from signals: SessionSignals) -> [VersionMention]:
    accumulator: [String /* normalized */: (raw, SourceRef, count)] = [:]
    regex = compiled strict-semver regex

    for sourceKind in scanOrder:
        texts = textsFromSignals(sourceKind, signals)
        // For .history, texts is signals.historyDisplayTexts with index tracking
        // For others, a single optional string

        for (textIndex, text) in texts:
            if text is nil or empty: continue
            for match in regex.allMatches(in: text):
                raw = match.substring
                normalized = lowercased(stripLeadingV(raw))
                if accumulator[normalized] exists:
                    accumulator[normalized].count += 1
                    // Do NOT overwrite raw or selectedSource; the first scan-order
                    // occurrence wins.
                else:
                    sourceRef = (sourceKind == .history)
                        ? SourceRef(kind: .history, index: textIndex)
                        : SourceRef(kind: sourceKind, index: nil)
                    accumulator[normalized] = (raw, sourceRef, 1)

    result = accumulator.map { (normalized, tuple) in
        VersionMention(raw: tuple.raw, normalized: normalized,
                       selectedSource: tuple.sourceRef,
                       occurrenceCount: tuple.count)
    }

    // Deterministic ordering (three-level tie-breaker):
    result.sort:
        1. selectedSource.kind priority (position in scanOrder, ascending)
        2. occurrenceCount (descending)
        3. normalized (lexicographic ascending)

    return result
```

**Determinism guarantee**: given the same `SessionSignals` input, `extract` produces byte-identical output on any two calls, on any platform. No randomness, no hash iteration order dependence.

### 3.4 `LLMPrompts.titleInput` rewrite

**Remove**: the inline milestone keyword filter at `LLMPrompts.swift:45-68` (head(2) + milestoneKeywords filter + tail(2) block).

**Add**: structured injection of both `versionMentions` and `MilestoneSampler` output. New `titleInput` shape:

```swift
public static func titleInput(from signals: SessionSignals, rawTurns: [String] = []) -> String {
    var parts: [String] = []

    // ... existing sessionID / scale / entrypoint / branch / filesModified / toolsUsed
    //     / firstUserIntent / lastUserIntent / lastAssistantProgress / task sections
    //     stay as-is ...

    // NEW: structured version mention injection (both zero and non-zero branches)
    if !signals.versionMentions.isEmpty {
        parts.append("识别到的版本号（有限列表，请严格依据）:")
        for vm in signals.versionMentions {
            let loc = renderSourceRef(vm.selectedSource)
            parts.append("  - \(vm.raw) → normalized=\(vm.normalized), 出现 \(vm.occurrenceCount) 次, selectedSource: \(loc)")
        }
    } else {
        parts.append("本 session 未识别到任何版本号。")
    }

    // REPLACED: inline milestone code is gone; call MilestoneSampler instead
    if !signals.historyDisplayTexts.isEmpty {
        let K = MilestoneSampler.adaptiveK(
            historyCount: signals.historyDisplayTexts.count
        )
        let milestones = MilestoneSampler.sample(
            history: signals.historyDisplayTexts,
            versionMentions: signals.versionMentions,
            K: K
        )
        parts.append("用户输入历史（\(signals.historyDisplayTexts.count) 条，选取 \(milestones.count) 个关键里程碑）:")
        for m in milestones {
            let label = renderMilestoneLabel(m.reasons)
            parts.append("  \(label) \(String(m.text.prefix(100)))")
        }
    }

    // rawTurns section unchanged
    if !rawTurns.isEmpty {
        let turnsSnippet = rawTurns
            .map { String($0.prefix(300)) }
            .joined(separator: "\n---\n")
        parts.append("关键对话片段（\(rawTurns.count) 条）:\n\(turnsSnippet)")
    }

    return parts.joined(separator: "\n")
}

private static func renderMilestoneLabel(_ reasons: [MilestoneEntry.Reason]) -> String {
    let pieces: [String] = reasons.map { reason in
        switch reason {
        case .firstEntry:
            return "首条"
        case .lastEntry:
            return "末条"

            return "版本锚点 \(normalized)"
        case .timeFill(let bucket, let total):
            return "时间补点 \(bucket + 1)/\(total)"
        }
    }
    return "[" + pieces.joined(separator: " | ") + "]"
}

private static func renderSourceRef(_ ref: SourceRef) -> String {

    case .history:

}
```

```swift
import Foundation

public struct MilestoneEntry: Sendable, Equatable {

    public let totalCount: Int      // snapshot of historyDisplayTexts.count

    public let reasons: [Reason]    // non-empty
```

### 4.3 Adaptive K formula

```swift
public enum MilestoneSamplerConstants {
    public static let kFloor = 4
    public static let kCeiling = 8
    public static let kDivisor = 10
}

public static func adaptiveK(historyCount: Int) -> Int {
    if historyCount <= 0 { return 0 }
    let raw = max(kFloor, historyCount / kDivisor)
    let capped = min(kCeiling, raw)
    return min(historyCount, capped)
}
```

### 4.4 Sampling algorithm

```
sample(history, versionMentions, K) -> [MilestoneEntry]:

    if history.isEmpty: return []

    var mandatory: [Int: [Reason]] = [:]

    // ─── Short session branch ───
    if history.count <= K:
        for i in 0..<history.count:
            var rs: [Reason] = []
            if i == 0 { rs.append(.firstEntry) }
            if i == history.count - 1 { rs.append(.lastEntry) }
            // Middle entries in a short session also get a timeFill reason
            // so that reasons is guaranteed non-empty regardless of version anchor overlap
            if i != 0 && i != history.count - 1 {
                rs.append(.timeFill(bucket: i, totalBuckets: history.count))
            }
            mandatory[i] = rs
        // Version anchors still layered on via Phase 2 below
        // Phase 3 (time fill) is skipped for short sessions
        runPhase2(&mandatory, versionMentions, history.count)
        return finalize(mandatory, history)

    // ─── Long session branch ───

    // Phase 1: head + tail mandatory
    mandatory[0] = [.firstEntry]
    mandatory[history.count - 1] =
        (mandatory[history.count - 1, default: []]) + [.lastEntry]

    // Phase 2: version anchors
    runPhase2(&mandatory, versionMentions, history.count)

    // Phase 2.5: truncation when mandatory exceeds K
    if mandatory.count > K:
        runTruncation(&mandatory, versionMentions, K)
        // Phase 3 is skipped when mandatory is already >= K after truncation
        return finalize(mandatory, history)

    // Phase 3: time-uniform fill for remaining slots
    runPhase3TimeFill(&mandatory, history, K)

    // Phase 4: finalize
    return finalize(mandatory, history)
```

**Phase 2 — version anchors**:

```
runPhase2(mandatory, versionMentions, historyCount):
    for vm in versionMentions:
        // Only history-anchored versions can become milestone anchors.
        // Versions whose selectedSource.kind is not .history have no history
        // index to anchor on; they remain visible to prompts via signals.versionMentions
        // but are not selected as milestone samples.
        if vm.selectedSource.kind != .history: continue
        guard let idx = vm.selectedSource.index, idx >= 0, idx < historyCount: continue
        mandatory[idx, default: []].append(
            .versionAnchor(normalizedVersion: vm.normalized)
        )
```

**Phase 2.5 — truncation**:

```
runTruncation(mandatory, versionMentions, K):

    // Step 1: firstEntry / lastEntry are always protected (max 2 slots)
    var protectedIndices = Set<Int>()
    for (idx, reasons) in mandatory:
        if reasons.contains(.firstEntry) || reasons.contains(.lastEntry):
            protectedIndices.insert(idx)

    let remainingSlots = K - protectedIndices.count
    let nonProtected = mandatory.keys.filter { !protectedIndices.contains($0) }

    // Step 2: for each non-protected index, find its "representative version"
    //         (the version with highest occurrenceCount at that index;
    //          ties broken by normalized lexicographic ascending)
    let scored: [(idx: Int, topOccurrence: Int, topNormalized: String)] =
        nonProtected.map { idx in
            let vms = versionMentions.filter {
                $0.selectedSource.kind == .history &&
                $0.selectedSource.index == idx
            }
            let top = vms.max(by: { a, b in
                if a.occurrenceCount != b.occurrenceCount {
                    return a.occurrenceCount < b.occurrenceCount
                }
                return a.normalized > b.normalized   // reverse for max to pick asc
            })!
            return (idx, top.occurrenceCount, top.normalized)
        }

    // Step 3: sort by priority (occurrence desc, normalized asc)
    let sorted = scored.sorted { a, b in
        if a.topOccurrence != b.topOccurrence {
            return a.topOccurrence > b.topOccurrence
        }
        return a.topNormalized < b.topNormalized
    }

    let kept = Set(sorted.prefix(remainingSlots).map { $0.idx })
    let finalKept = protectedIndices.union(kept)

    // Remove entries not in finalKept (does NOT affect signals.versionMentions)
    mandatory = mandatory.filter { finalKept.contains($0.key) }
```

**Key property of Phase 2.5**: version anchors that get truncated remain fully present in `SessionSignals.versionMentions`. Truncation only affects which history entries are selected as example milestones in the prompt. The version clause in the system prompt (§3.5) still operates on the full `versionMentions` list.

**Phase 3 — time-uniform fill**:

```
runPhase3TimeFill(mandatory, history, K):

    if mandatory.count >= K: return

    let slotsRemaining = K - mandatory.count
    let bucketWidth = Double(history.count) / Double(slotsRemaining)

    for bucket in 0..<slotsRemaining:
        let center = min(
            Int((Double(bucket) + 0.5) * bucketWidth),
            history.count - 1
        )
        if let idx = findNearestUnoccupied(
            center: center,
            occupied: Set(mandatory.keys),
            range: 0..<history.count
        ) {
            mandatory[idx] = [.timeFill(bucket: bucket, totalBuckets: slotsRemaining)]
        }
        // else: this bucket has no unoccupied slot, skipped (rare)
```

**`findNearestUnoccupied`**:

```
findNearestUnoccupied(center, occupied, range) -> Int?:

    // Check center first
    if center in range and center not in occupied: return center

    // Expand outward symmetrically. On equal distance (offset > 0),
    // prefer the earlier index (center - offset) for determinism.
    for offset in 1..<range.count:
        let leftCandidate = center - offset
        if leftCandidate in range and leftCandidate not in occupied:
            return leftCandidate
        let rightCandidate = center + offset
        if rightCandidate in range and rightCandidate not in occupied:
            return rightCandidate

    return nil
```

**Deterministic ordering of `reasons` inside each entry** (the `sortReasons` contract):

1. `.firstEntry` (at most 1)
2. `.versionAnchor(normalized:)` for all applicable, sorted by `normalized` lexicographic ascending
3. `.lastEntry` (at most 1)
4. `.timeFill(bucket:totalBuckets:)` (at most 1)

**Canonical rendering examples**:

- First + two version anchors: `[首条 | 版本锚点 0.2.5 | 版本锚点 0.2.6]`
- Last + one version anchor: `[版本锚点 0.2.6 | 末条]`
- Time fill + version anchor: `[版本锚点 0.2.5 | 时间补点 2/5]`
- Short session single entry both first and last: `[首条 | 末条]`
- Short session middle entry, no version: `[时间补点 2/5]`

**Finalize**:

```
finalize(mandatory, history) -> [MilestoneEntry]:
    return mandatory.keys.sorted().map { idx in
        MilestoneEntry(
            index: idx,
            totalCount: history.count,
            text: history[idx],
            reasons: sortReasons(mandatory[idx]!)
        )
    }
```

## Section 5 — `readSampledUserTurns` Bucket-Center Two-Pass Streaming

### 5.1 Contract and signature

**File**: `Sources/ClaudeSessionHub/Providers/JSONLParser.swift` (in-place function body rewrite)

**Signature preserved** (callers unchanged):

```swift
public static func readSampledUserTurns(
    at path: String,
    count: Int,              // target sample count K
    skipHead: Int = 10,
    skipTail: Int = 50
) throws -> [[String: Any]]
```

**Algorithm guarantees**:
- **Memory**: retained parsed JSON entries in memory ≤ K at any time, plus at most 1 transient parsed entry currently being evaluated. The algorithm parses many middle-window lines in the course of bucket-center evaluation, but un-selected transient entries are released immediately by Swift ARC and do not accumulate. Memory is O(K) regardless of file size.
- **IO**: two streaming passes over the file.
- **Determinism**: same file produces byte-identical output on repeated calls.
- **No `readAllEntries` call**: the new function body must not reference `readAllEntries`. Enforced by code review (the behavior is also implicit in the memory bound: `readAllEntries` would violate O(K) memory).
- **Result may be shorter than K**: buckets with no qualifying user turn contribute no entry. The caller (`extractKeyTurns`) already tolerates short middle-sample results via its head/tail merge logic.

**Qualifying user turn** (unchanged from v0.2.7 behavior):
- `entry["type"] as? String == "user"`
- `entry["isMeta"] as? Bool != true`

### 5.2 Algorithm pseudocode

```
readSampledUserTurns(path, K, skipHead, skipTail) throws -> [JSONObject]:

    handle = open(path, forReading)
    defer: handle.close()

    // ─── Pass 1: byte scan for total line count ───
    var totalLines = 0
    var sawAnyByte = false
    var lastByte: UInt8 = 0
    handle.seek(to: 0)
    while chunk = handle.read(chunkSize: 65536), !chunk.isEmpty:
        sawAnyByte = true
        for byte in chunk:
            if byte == 0x0A /* \n */: totalLines += 1
        lastByte = chunk.last
    // If file had content but did not end with newline, count the final line
    if sawAnyByte && lastByte != 0x0A:
        totalLines += 1

    // ─── Bounds check ───
    let middleStart = skipHead
    let middleEnd = totalLines - skipTail   // [middleStart, middleEnd)
    let middleSize = middleEnd - middleStart
    if middleSize <= 0: return []

    let actualK = min(K, middleSize)
    if actualK <= 0: return []

    // ─── Compute bucket centers ───
    let bucketWidth = Double(middleSize) / Double(actualK)
    var bucketCenters: [Int] = []
    for i in 0..<actualK:
        let center = middleStart + Int((Double(i) + 0.5) * bucketWidth)
        bucketCenters.append(min(center, middleEnd - 1))

    // ─── Pass 2: streaming middle window with bucket-center selection ───
    var bestEntry: [Int: [String: Any]] = [:]
    var bestDistance: [Int: Int] = [:]
    var buffer = Data()
    var lineIndex = 0

    func processLine(_ lineData: Data) {
        defer { lineIndex += 1 }

        // Outside middle window: skip
        if lineIndex < middleStart: return
        if lineIndex >= middleEnd: return

        // Parse JSON; skip malformed lines
        guard let parsed = try? JSONSerialization.jsonObject(with: lineData)
                as? [String: Any] else { return }

        // Qualifying user turn filter
        guard parsed["type"] as? String == "user",
              parsed["isMeta"] as? Bool != true else { return }

        // Determine bucket
        let offsetInMiddle = lineIndex - middleStart
        var bucketIdx = Int(Double(offsetInMiddle) / bucketWidth)
        bucketIdx = min(bucketIdx, actualK - 1)   // clamp

        let dist = abs(lineIndex - bucketCenters[bucketIdx])

        if let currentBest = bestDistance[bucketIdx] {
            if dist < currentBest {
                bestEntry[bucketIdx] = parsed
                bestDistance[bucketIdx] = dist
            }
            // Tie (dist == currentBest) or worse: do nothing.
            // Since Pass 2 iterates lineIndex ascending, the earlier entry
            // is already stored and is preserved on ties (earlier wins).
        } else {
            bestEntry[bucketIdx] = parsed
            bestDistance[bucketIdx] = dist
        }
    }

    handle.seek(to: 0)
    while chunk = handle.read(chunkSize: 65536), !chunk.isEmpty:
        buffer.append(chunk)
        while let newlineRange = buffer.range(of: Data([0x0A])):
            let lineData = buffer.subdata(in: 0..<newlineRange.lowerBound)
            buffer.removeSubrange(0..<newlineRange.upperBound)
            processLine(lineData)

            // Early exit: once we've passed middleEnd, no further processing needed
            if lineIndex >= middleEnd: break    // inner while
        if lineIndex >= middleEnd: break        // outer while

    // ─── EOF flush: handle final line without trailing \n ───
    if !buffer.isEmpty && lineIndex < middleEnd:
        processLine(buffer)
        buffer.removeAll()

    // ─── Finalize ───
    var result: [[String: Any]] = []
    for i in 0..<actualK:
        if let entry = bestEntry[i] {
            result.append(entry)
        }
        // else: bucket had no qualifying user turn, slot left empty
    return result
```

**Notes on tie handling**:
- "Earlier entry wins on equal distance" is achieved naturally because the stream processes lines in ascending `lineIndex`, and the `else if dist == currentBest` branch intentionally does nothing. No `break` or `continue` is used in that branch because both would break the outer parsing loop. The branch is a pure no-op.
- This behavior is documented in both spec and source comments to prevent future agents from thinking it is a missing case.

### 5.3 Edge cases

| Case | Behavior |
|---|---|
| File does not exist | Throws `CocoaError(.fileReadNoSuchFile)` (unchanged from v0.2.7) |
| Empty file (`totalLines == 0`) | Returns `[]` |
| `totalLines <= skipHead + skipTail` | `middleSize <= 0`, returns `[]` |
| `middleSize < K` | `actualK = middleSize`, each middle qualifying user turn occupies its own bucket |
| Middle window contains no qualifying user turn | Returns `[]` (all buckets empty) |
| Some buckets have no qualifying user turn | Result has fewer than K entries; caller handles |
| Malformed JSON on a single line | That line is skipped; parsing continues |
| File has no trailing newline on the last line | Pass 1 counts the final line; Pass 2 flushes remaining buffer after chunk loop |

### 5.6 Performance and memory expectations

| Scenario | v0.2.7 (readAllEntries path) | v0.2.8 (two-pass) |
|---|---|---|
| 100 lines | 100 parsed dicts in memory | ≤5 retained + 1 transient |
| 1 000 lines | 1 000 parsed dicts | ≤5 + 1 |
| 10 000 lines | 10 000 parsed dicts | ≤5 + 1 |
| 100 000 lines | 100 000 parsed dicts (OOM risk) | ≤5 + 1 |
| IO | 1 full file read | 2 streaming reads |

The 2x IO is nearly free in practice because macOS page cache turns Pass 2 into a memory copy. JSON parse cost dominates wall-clock time, and the two-pass approach parses the same lines the old approach did (only in the middle window), so parse time is similar or better.

**Layer 1 does not assert peak memory** at runtime (reliable memory measurement in Swift tests is brittle and high-maintenance). The memory guarantee is enforced by algorithm contract and code review, not by runtime assertion.

```swift
import Foundation

// Input: argv[1] = LLMPrompts.swift path; argv[2] = output GeneratedPromptSource.swift path
// Hard-fails on any error. No silent fallback.

guard CommandLine.arguments.count == 3 else {
    FileHandle.standardError.write("ExtractPromptSourceTool: usage: <input> <output>\n".data(using: .utf8)!)
    exit(1)
}
let inputPath = CommandLine.arguments[1]
let outputPath = CommandLine.arguments[2]

// 1. Read source file (fail if missing)
guard let source = try? String(contentsOfFile: inputPath, encoding: .utf8) else {
    FileHandle.standardError.write(
        "ExtractPromptSourceTool: cannot read \(inputPath)\n".data(using: .utf8)!
    )
    exit(2)
}

// 2. Locate `public static func titleInput(` signature and extract body
//    by brace matching. On failure, exit non-zero.
guard let bodyString = extractTitleInputFunctionBody(from: source) else {
    FileHandle.standardError.write(
        "ExtractPromptSourceTool: cannot find titleInput function in \(inputPath)\n".data(using: .utf8)!
    )
    exit(3)
}

guard !bodyString.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty else {
    FileHandle.standardError.write(
        "ExtractPromptSourceTool: extracted body is empty\n".data(using: .utf8)!
    )
    exit(4)
}

// 3. Generate output Swift file
let escaped = bodyString
    .replacingOccurrences(of: "\\", with: "\\\\")
    .replacingOccurrences(of: "\"\"\"", with: "\\\"\\\"\\\"")

let generated = """
// Auto-generated by ExtractPromptSourceTool — do not edit.
// Source: \(inputPath)
public enum GeneratedPromptSource {
    public static let titleInputFunctionSource: String = \"\"\"
\(escaped)
\"\"\"
}
"""

do {
    try generated.write(toFile: outputPath, atomically: true, encoding: .utf8)
} catch {
    FileHandle.standardError.write(
        "ExtractPromptSourceTool: cannot write \(outputPath): \(error)\n".data(using: .utf8)!
    )
    exit(5)
}

exit(0)
```

The brace-matching `extractTitleInputFunctionBody` helper is implemented inside the tool; it locates the first `public static func titleInput(` occurrence and returns the body including the outermost braces.

**Hard-fail contract**:
- Input file missing → exit 2
- Function signature not found → exit 3
- Extracted body empty → exit 4
- Output write failure → exit 5
- Any exit non-zero → SwiftPM build command fails → SwiftPM build fails

No runtime fallback is allowed. No `#if` guarding the presence of `GeneratedPromptSource`. The hash check depends on this constant being present and correct; any weakening of this chain invalidates the gate.

## Section 7 — Invariants, Deferred, Spec Process

This section produces no new decisions. It aggregates the load-bearing constraints from Sections 1–6 so future agents can treat them as a single locked set.

### 7.1 Invariants (v0.2.8 must-hold rules)

Ordered from strongest commitment (hardest to reverse) to weakest.

**I-1 — Scope boundary**
> v0.2.8 is the AI quality infrastructure version (single mainline). The four scope items are: two-layer eval infrastructure, initial 6-fixture set, `versionMentions` structured signal, sampling chain reconstruction. UI, UX, provider matrix, and tech debt changes **must** be deferred. Any PR introducing out-of-scope work in the v0.2.8 branch must be reverted or rescheduled.

**I-2 — Two-layer verification**
> Layer 1 (deterministic Swift tests) runs in CI on every PR, no LLM calls. Layer 2 (`swift run eval-harness live --release`) runs on a pre-tag candidate commit, calls the canonical provider. The two layers cannot be merged, cannot substitute each other, and cannot skip each other.

**I-3 — Canonical provider locked**
> v0.2.8 release gate's canonical provider is DashScope qwen-plus, temperature=0, dslSchemaVersion "1". These values are hardcoded in `EvalHarnessCore.CanonicalGate` and mirrored in `check-artifact`. `EVAL_PROVIDER` and `EVAL_MODEL` environment variables are honored only in `--dev` mode. In `--release` mode the env vars are ignored (with a warning to stderr) and the canonical constants are used.

**I-4 — Release gate eight-way binding**
> Tag creation requires a matching artifact in `docs/eval/gate-runs/` satisfying all eight conditions:
> - `mode == "release"`
> - `commitSHA == (git rev-parse HEAD^)` — where HEAD is the artifact commit and HEAD^ is the candidate commit
> - `promptBuilderHash == sha256(canonicalBlob)` where canonicalBlob is computed at check time from current source
> - `dslSchemaVersion == CanonicalGate.dslSchemaVersion`
> - `provider == CanonicalGate.provider`
> - `model == CanonicalGate.model`
> - `temperature == CanonicalGate.temperature`
> - `gateResult == "PASS"`
>
> All eight are verified mechanically by `eval-harness check-artifact --tag <v>`. Any failure → non-zero exit → tag refused.

**I-5 — `promptBuilderHash` definition**
> `promptBuilderHash = "sha256:" + hex(sha256(canonicalBlob.utf8))` where `canonicalBlob` is the concatenation of four labeled sections: `titleSystemPrompt`, `progressSystemPrompt`, `summarySystemPrompt`, and the Swift source text of `LLMPrompts.titleInput`'s function body. The fourth element is captured at build time by `ExtractPromptSourceTool` via the plugin pipeline. The tool's hard-fail behavior (exit non-zero on any extraction failure) propagates through the plugin to SwiftPM, causing the build to fail. There is no runtime fallback to "just hash the 3 system prompts"; any weakening of this chain invalidates the gate.

**I-6 — Fixture identity three-way consistency**
> For every fixture, `filename prefix == input.id == expected.id`. Violations cause `HarnessConfigError.fixtureIDMismatch` at harness startup, aggregated with other config errors.

**I-7 — DSL fail-closed**
> Missing or unknown `schemaVersion` in a fixture causes `schemaMissing` or `schemaTooNew`, aborting the run. No automatic schema migration. DSL evolution is via `schemaVersion` bump plus old-and-new-fixture coexistence. The harness refuses to silently upgrade anything.

**I-8 — Verifier aggregates, never fail-fasts**
> Within a single fixture, all fields and all constraints are evaluated; every violation is collected. Across fixtures, all fixtures run; one failing fixture does not abort the run. `HarnessConfigError` cases are aggregated at startup under the same rule.

**I-9 — Violations are structured**
> `VerificationResult` always contains `violations: [Violation]`. A `Violation` always contains `field`, `constraint`, `expected` (human-readable description), and `actual` (output excerpt). `passed: Bool` alone is insufficient; release gate diagnostics depend on the violation list.

**I-10 — Desensitization fidelity**
> Desensitization is scripted (`scripts/eval/desensitize_session.swift`). The mapping tables are local-only (never committed). The script and the produced snapshot are committed. Timestamps may be shifted uniformly (preserving Δt) or normalized to a base, but never reordered and never rescaled. Public semver tokens are preserved byte-for-byte. The standalone pre-check verifier is independent of product code (no shared implementation), independently maintained, and changes require a separate PR with a re-run of all fixture structural comparisons. Pilot exit criteria: N=2 distinct failure modes must reproduce on desensitized snapshots before the pipeline is accepted.

**I-11 — Responsibility boundaries**
> - `VersionMentionExtractor` is a pure function: input is an assembled `SessionSignals`, output is `[VersionMention]`. No I/O. No file access. No store access.
> - `MilestoneSampler` is a pure function: input is `(history, versionMentions, K)`, output is `[MilestoneEntry]`. No knowledge of LLM, prompts, or providers.
> - `LLMPrompts` only renders; it never samples. All sampling decisions come from `MilestoneSampler`.
> - `VersionMentionExtractor` is populated into `SessionSignals.versionMentions` at exactly one call site: the tail of `ClaudeProvider.extractSignals(for:)`, just before `return signals`.
> - `SignalExtractor` continues to read raw sources only. It does not populate `versionMentions`.
> - Tests follow the same boundaries: `VersionMentionExtractorTests` tests the pure function; `ClaudeProviderTests` tests the end-to-end population. There is no `SignalExtractorTests` test for `versionMentions`.

**I-12 — `readSampledUserTurns` memory contract**
> Retained parsed JSON entries in memory ≤ K (plus at most 1 transient parsed entry under evaluation). The function body must not call `readAllEntries`. Implementation is two-pass streaming: Pass 1 counts total lines via byte scan; Pass 2 streams the middle window with bucket-center selection. Tie distance prefers earlier index (stream order). Final-line-without-newline is handled by an explicit EOF flush after the chunk loop.

**I-13 — `MilestoneEntry.reasons` non-empty and deterministic**
> `MilestoneEntry.reasons` is always non-empty (enforced by `precondition` in the initializer). The internal sort order is: `.firstEntry` → `.versionAnchor(normalized:)` sorted by `normalized` ascending → `.lastEntry` → `.timeFill(bucket:totalBuckets:)`. When mandatory > K, truncation preserves firstEntry/lastEntry (up to 2 slots), then gives remaining slots to version anchors sorted by representative `occurrenceCount` descending, then by representative `normalized` ascending. Truncated version anchors remain fully present in `signals.versionMentions`; only milestone selection is affected.

**I-14 — Zero-version-detection branch covers all three fields**
> When `signals.versionMentions` is empty, the shared "version number clause" in the three system prompts forbids introducing any version number, version range, or version-like language in any of `title`, `progress`, or `summary`. This is the primary mechanical defense against version-number hallucination.

**I-15 — "No pass, no tag" — mechanical + process**
> Release gate is a combination of mechanical gate and process door:
> - **Mechanical**: `eval-harness check-artifact --tag <v>` must find exactly one matching artifact (strict unique match on `tagLabel + mode + commitSHA`) and pass all 8 binding checks. 0 matches fails; ≥2 matches fails with a listing of candidate paths and a prompt to delete stale artifacts or pass `--artifact <path>` explicitly. The `--artifact` escape hatch bypasses the directory scan but still enforces the triple-filter on the selected file.
> - **Process**: Tag commits must include the matching artifact file in `docs/eval/gate-runs/`. `finishing-a-development-branch` and `requesting-code-review` skill checklists each gain one line: "run `eval-harness live --release --tag <v>` and then `eval-harness check-artifact --tag <v>`, commit the artifact, then create the tag on the artifact commit."

```swift
import Foundation

public enum HarnessConfigError: Error, CustomStringConvertible, Sendable {
    case unpairedFixture(id: String, missing: PairSide)
    case schemaMissing(id: String, file: String)
    case schemaTooNew(id: String, found: String, supported: String)
    case malformedInput(id: String, reason: String)
    case malformedExpected(id: String, reason: String)
    case fixtureIDMismatch(prefix: String, inputID: String?, expectedID: String?)
    case invalidKindMetaCombination(id: String, reason: String)
    case invalidRegex(id: String, field: String, pattern: String, error: String)
    case invalidConstraintValue(id: String, field: String, constraint: String, reason: String)
    case verbatimMatchRequiresJustification(id: String, field: String, value: String, length: Int)
    case promptSourceMissing

    public var description: String {
        switch self {
        case .unpairedFixture(let id, let missing):
            return "fixture '\(id)': missing \(missing.rawValue) file"
        case .schemaMissing(let id, let file):
            return "fixture '\(id)' file '\(file)': schemaVersion field is missing"
        case .schemaTooNew(let id, let found, let supported):
            return "fixture '\(id)': schemaVersion '\(found)' is newer than harness support '\(supported)'. Upgrade the harness or downgrade the fixture."
        case .malformedInput(let id, let reason):
            return "fixture '\(id)' input.json is malformed: \(reason)"
        case .malformedExpected(let id, let reason):
            return "fixture '\(id)' expected.json is malformed: \(reason)"
        case .fixtureIDMismatch(let prefix, let inputID, let expectedID):
            return "fixture prefix '\(prefix)': id mismatch — input.id=\(inputID ?? "nil"), expected.id=\(expectedID ?? "nil"). All three must be equal."
        case .invalidKindMetaCombination(let id, let reason):
            return "fixture '\(id)': kind/meta invalid: \(reason)"
        case .invalidRegex(let id, let field, let pattern, let error):
            return "fixture '\(id)' field '\(field)': regex /\(pattern)/ failed to compile: \(error)"
        case .invalidConstraintValue(let id, let field, let constraint, let reason):
            return "fixture '\(id)' field '\(field)' constraint '\(constraint)': invalid value: \(reason)"
        case .verbatimMatchRequiresJustification(let id, let field, let value, let length):
            return "fixture '\(id)' field '\(field)': \(length)-char constraint string '\(String(value.prefix(40)))...' appears verbatim in input text. Add 'verbatimMatchJustification' field with a human-readable reason, or remove the verbatim copy."
        case .promptSourceMissing:
            return "GeneratedPromptSource constant is missing — build plugin failed silently. This should not be possible; investigate build pipeline."
        }
    }
}
```
